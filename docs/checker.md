# Проверка за десять минут

Три команды отвечают на три разных вопроса:

| Вопрос | Команда | Время |
|---|---|---|
| Собирается ли и проходит ли гейт? | `make verify` | 3–5 мин |
| Работает ли продукт от базы до кабинета? | `make demo` | 2 мин |
| Правда ли числа, которые обещает README? | `make verify-demo` | 3 мин |

Ключ модели не нужен. Демо отвечает детерминированным экстрактивным провайдером, эмбеддинги
хеширующие, сеть не требуется. Живые модели — опция в конце.

## 0. Что должно стоять на машине

Docker с compose v2, `make`, `uv`, `python3`, `curl`, Node 22 для кабинета. Локальный Python-venv
создаёт `make install`.

```bash
make doctor
```

Ожидаемо — строка `doctor: ready.` Если есть `FAIL`, там же написано, чего не хватает. Доктор
ничего не запускает и не удаляет.

## 1. Гейт: `make verify`

Один вход, ровно то, что гоняет CI, плюс проверка кабинета. Нужна база: либо compose-сервис
`postgres`, либо контейнер с pgvector.

```bash
docker compose up -d postgres
export ONBOARDING_TEST_DATABASE=postgresql+asyncpg://onboarding:onboarding@localhost:55432/onboarding
DATABASE_URL="$ONBOARDING_TEST_DATABASE" make migrate
make verify
```

Порт `55432` — это compose; контейнер `onboarding-pg` из раздела «Без compose» держит `5432`, чтобы
пути не сталкивались.

Ожидаемый результат:

```text
ruff: All checks passed!
mypy: Success: no issues found in N source files
import-linter: Contracts: 2 kept, 0 broken.
docs-index ok: N документов
docs ok: N documents
pytest: passed, покрытие >= 85%
admin: lint, typecheck и vitest зелёные
```

Без `ONBOARDING_TEST_DATABASE` команда остановится и попросит базу. Это намеренно: интеграционный
тир без базы ничего не доказывает, а зелёный без него — неправда.

## 2. Демо: `make demo`

Поднимает стек, наполняет базу, печатает дверь и токен:

```bash
make demo
# open http://localhost:3000 and enter dev-hr-token
```

Что должно быть в кабинете: 3 сотрудника, 69 активных документов, 2 сигнала высокого риска,
2 вопроса без ответа. Эти же числа проверяет `scripts/verify_demo.sh`.

Пошаговый маршрут, что показывать на каждом экране, — [demo-script.md](product/demo-script.md).
Пустое состояние: `make demo-data-del`. Полный сброс: `make nuke`.

## 3. Числа: `docs/measurements/current.md`

README не переписывает цифры, а ссылается на сводку. В сводке у каждой строки есть файл измерения,
а в файле — команда, коммит и окружение. Там же сказано, какие гейты прогон не прошёл: последний
полный прогон провалил два гейта задержки, и это записано, а не спрятано.

Что проверяется без ключа модели:

```bash
make eval-lint        # контракт набора и сила каждого гейта, 52 теста
make eval-retrieval   # поиск; на хеширующем эмбеддере это диагностика, а не оценка качества
```

`make eval-retrieval` на `hashing` печатает `FAILED recall_at_5`. Это ожидаемо: хеши не умеют
семантику, гейты выставлены под настоящий эмбеддер. Числа настоящего прогона — в
[measurements](measurements/current.md).

## 4. Живые модели, без бюджета (опция)

```bash
cp .env.live.example .env.live   # вписать LLM_API_KEY
make demo-live
```

Профиль `openrouter-free` ходит в бесплатную модель через OpenRouter. Три честных ограничения:

- суточный лимит бесплатного тира: хватает на разговор, не хватает на `make eval`;
- бесплатных эмбеддингов OpenRouter не даёт, поэтому поиск остаётся локальным: ответы живые,
  ранжирование — демонстрационное;
- `429` от бесплатного тира — норма, а не баг: отказ уходит в эскалацию.

Платный профиль на том же ключе (`openrouter-gpt-4.1-mini`) стоит около 0.07 ₽ за ответ; как
включить — в комментариях `.env.live.example`.

## 5. Чего здесь нет

Названо, чтобы никто не додумал лишнего:

| Не проверяется | Почему |
|---|---|
| Настоящий бот MAX | нужен верифицированный токен «MAX для бизнеса»; адаптер проверен на задокументированных payload |
| Загрузка файлов из бота в чат | не сделана; сценарий описывает документы, бот их не прикладывает |
| Юридическое окно хранения | механизм протестирован, число за компанией |
| Продакшн-эксплуатация | есть один демо-стенд на VM, SLA и 152-ФЗ-контур — вне этой работы; что он показывает — [live-demo.md](live-demo.md) |
| Качество на настоящей модели без ключа | воспроизводится только своим прогоном по `docs/evals/README.md` |

## Если что-то не так

| Симптом | Причина | Действие |
|---|---|---|
| `Bind for 0.0.0.0:55432 failed` | порт занят другим Postgres | `make nuke`, затем `make demo` |
| `migrate` падает с `Name or service not known` | postgres не поднялся из-за занятого порта | `docker compose rm -sf postgres && make demo` |
| `401` в кабинете | токен не из `ADMIN_TOKENS` | вставить `dev-hr-token` |
| `429` от модели | лимит бесплатного тира | ждать сутки или платный профиль |
| `knowledge index was built with 'hashing:1024'` | базу индексировали другим эмбеддером | `make demo-data` |
| `ONBOARDING_TEST_DATABASE is required` | гейт без базы | шаг 1 этой страницы |
