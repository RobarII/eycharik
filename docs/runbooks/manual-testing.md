# Прогон: человек впервые разговаривает с ботом

Этот прогон отвечает на вопрос «работает ли бот для живого человека», а не «проходит ли код
тесты». Его делает коллега со своего (или чужого) аккаунта MAX, пока разработчик смотрит в
кабинет. Всё, что нужно, — аккаунт, доступ в кабинет и этот файл.

## Что передать

1. **Аккаунт MAX**, который уже привязан к сотруднику. Чужой аккаунт бот проигнорирует: доступ —
   факт компании, а не чата ([0019](../decisions/0019-a-channel-is-an-address.md)).
2. **Адрес кабинета**: `https://bot.state3407.space/admin/` — вход по токену, без пароля.
3. **Токен кабинета** и, если он нужен, SSH-доступ к `/opt/onboarding`. Токен лежит в
   `ADMIN_TOKENS` файла `.env.prod` на хосте; передаётся личным каналом, не в репозитории и не в
   переписке с ботом.
4. **Этот файл** как чек-лист. Ссылки на контракты: `docs/contracts/max-api.md`,
   `docs/contracts/admin-api.md`, `docs/product/scenarios.md`.

Репозиторий не обязателен, чтобы нажимать кнопки. Он нужен, чтобы прочитать ожидаемое поведение и
приложить к отчёту точный шаг сценария.

## Подготовка

- Убедиться, что канал MAX включён: `https://bot.state3407.space/healthz` отвечает `200`.
- Открыть кабинет, найти сотрудника, к которому привязан аккаунт, и запомнить `run_id` из адреса
  карточки.
- Решить, что делать с текущим прогоном. Если он уже идёт, бот ответит на `/start` текущим шагом,
  а не начнёт заново. Для чистого прогона нужен новый сотрудник или сброс разработчиком.

## Сценарии

Отмечать «ок / не ок» и прикладывать скриншот ответа бота.

| № | Действие | Ожидаемо в чате | Ожидаемо в кабинете |
|---|---|---|---|
| 1 | Очистить чат с ботом и отправить `/start` | приветствие и первый шаг, клавиатура | шаг `welcome`, событие `run_started` или `run_restarted` |
| 2 | Нажать кнопку выбора обращения | следующий шаг, вопросы про документы | шаг `documents_checklist`, `tone` выбран, событие `button_pressed` |
| 3 | Отправить фото паспорта без подписи | шаг двигается, бот пишет следующий шаг | шаг `day_before`, в «Документах» файл `passport.jpg`, статус «stored» |
| 4 | Нажать «Скачать» в кабинете | — | файл скачивается и открывается, в аудите `file_downloaded` |
| 5 | Отправить PDF (диплом) с подписью «вот диплом» | шаг двигается, подпись не ломает ответ | новый файл в списке, `media_type` `application/pdf` |
| 6 | Отправить фото с подписью-вопросом «а это подойдёт?» | бот отвечает на вопрос, шаг не двигается | шаг тот же, вопрос в «Что спрашивал» |
| 7 | Отправить текстовый вопрос по онбордингу («где получить пропуск?») | ответ по корпусу, без выдумки | вопрос с цитатами или эскалация |
| 8 | Отправить файл недопустимого типа (например `.exe` или `.txt`) | бот не засчитывает файл | файл со статусом «не принят», шаг не двигается |
| 9 | Отправить файл больше 15 МБ | бот не засчитывает файл | статус «не принят», причина `declared_size` |
| 10 | Написать `/start` посреди прогона | бот повторяет текущий шаг с клавиатурой | `run_restarted`, прогресс сохранён |
| 11 | Написать «привет» без команды | ответ как на сообщение, прогон не сбрасывается | шаг тот же |
| 12 | Проверить чужой аккаунт (не привязанный) | бот молчит | аудит `unlinked_channel_user`, прогона нет |

## Где смотреть

- **Карточка прогона** — шаг, прогресс, аккаунт мессенджера, документы, хронология.
  `https://bot.state3407.space/admin/#/run/<run_id>`.
- **Аудит на хосте** — события `file_stored`, `file_not_stored`, `file_downloaded`,
  `step_transition`, `job_failed`:

```bash
ssh vps 'docker exec onboarding-postgres-1 psql -U onboarding -d onboarding -c \
  "select at, name, fields from audit_log order by id desc limit 20;"'
```

- **Логи воркера**, если ответ не пришёл:

```bash
ssh vps 'cd /opt/onboarding && docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  --env-file .env.prod logs --tail=100 worker api'
```

## Что уже известно и не является багом

- Файлы не распознаются: бот не читает паспорт и не проверяет комплектность. Один файл закрывает
  шаг «Документы», даже если позиций шесть. Это записанное решение, а не случайность
  ([0027](../decisions/0027-inbound-documents-are-encrypted.md)).
- Файл хранится зашифрованным и удаляется при офбординге; скачать его может только кабинет.
- MAX ограничивает темп: не больше двух сообщений в секунду. Серия быстрых кнопок может прийти с
  задержкой.
- Повторный `/start` не начинает с нуля: он переигрывает текущий шаг.
- Документы, отправленные до релиза 2026-10-24, не сохранены: тогда бот считал только факт.

## Как отчитаться

Прислать одним сообщением:

1. дата и время (с часовым поясом), `run_id`;
2. что отправили — текст дословно или файл;
3. что ожидали и что увидели — скриншот чата и карточки;
4. строки аудита за это время, если есть доступ к хосту.

Формулировка «не работает» не принимается: нужен шаг сценария и наблюдаемое поведение. Если бот
молчит, сначала проверить `healthz`, потом аудит, потом логи — в этом порядке.
