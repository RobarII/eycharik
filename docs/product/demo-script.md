# Демо за пять минут

Сценарий для защиты: показать новичка, ассистента и кабинет рекрутера на одном наборе.
Всё работает без ключа модели и без токена MAX: ответы собирает детерминированный
extractive-провайдер из тех же фрагментов, что получила бы модель.

## Подготовка

Ничего готовить не нужно, кроме Docker с compose v2. `make demo` поднимает Postgres, накатывает
миграции, индексирует `knowledge/` и наполняет демо-набор. Файл `.env` не нужен: умолчания
compose — уже офлайн-профиль.

Если `make` нет (частое дело на Windows), те же шаги делает `demo-data.cmd` после
`docker compose up -d --build`.

## Запуск

```bash
make demo   # стек, миграции, ingest, 3 сотрудника, три вопроса, два риска
```

Открыть <http://localhost:3000>, вставить токен `dev-hr-token` (рекрутёрский скоуп —
`dev-recruiter-token`). `make verify-demo` делает то же самое и дополнительно сверяет числа через
admin API.

### Без compose (локальный Python)

Нужно, если правите код с перезагрузкой:

```bash
make install
make admin-install
docker run -d --name onboarding-pg \
  -e POSTGRES_PASSWORD=onboarding -e POSTGRES_USER=onboarding \
  -e POSTGRES_DB=onboarding -p 5432:5432 pgvector/pgvector:pg16
make migrate   # DATABASE_URL из .env.example: localhost:5432
make demo-data
make run       # терминал 1: API на :8000
make worker    # терминал 2: события и таймеры
make admin-dev # терминал 3: кабинет на :5173
```

Compose публикует свою базу на `55432` именно затем, чтобы этот контейнер на `5432` ему не мешал.

## Что показывать

1. **Кабинет, список.** Рекрутер `rec-1` видит своих: Анна Смирнова и Пётр Кузнецов уже
   ответили на вопросы третьего дня и стоят на опросе двух недель — ответы разобраны в рисках,
   а не спрятаны. Анна идёт по заводской ветке (`onboarding_plant` v1), Пётр — по офисной
   (`onboarding_default` v2), Мария Волкова — у HR. Прогресс считается по сценарию, а не по
   ответам модели: «Шаг 15 из 20», «Опрос двух недель». На старте бот спросил «ты» или «вы»;
   выбор живёт в прогоне (у демо — «ты»), следующий шаг приходит в выбранной форме. Открыть
   Анну — в карточке «Сценарий: Завод (ГТП)»: та же временная шкала, свой транспорт и без
   вопроса про удалёнку.
2. **Риски.** Вкладка «Риски» — главный кадр продукта. Сверху счётчики за семь дней: в процессе,
   завершили, высокий и средний риск, вопросы без ответа. Ниже дайджест: у Петра высокий риск с
   тегами «Доступы, ИТ, Руководитель» и цитатой из ответа, у Анны средний риск «оценка 6 из 10
   ниже порога 8». Обе строки получены реальным конвейером: ответ на опрос, классификатор, правила,
   аудит. В демо без ключей сигнал считает словарный пол `core/risk.py`, а не модель: модель без
   ключа не изображается. С ключом `CLASSIFY_API_KEY` тот же кадр показывает `sentiment_classified`
   с моделью и версией рубрики (ADR 0029). Кнопка «Открыть» ведёт в карточку сотрудника.
3. **Карточка Анны.** Шаг 13 из 20, текст опроса и вопросы: «Сколько дней отпуска в первый
   год?» — отвечен с цитатой `hr/leave-policy#0`; «Кто мой наставник?» — передан человеку:
   личный вопрос, ответ зависит от конкретного сотрудника, а не от регламента.
4. **Очередь вопросов.** На вкладке «Все» три вопроса: один отвеченный с цитатой и два
   переданных — личная тема и закрытый HR-документ.
   У переданного нажмите «Ответить в MAX», напишите ответ и отправьте: карточка уходит из «Без
   ответа», в «Отвеченных» появляются время закрытия и автор, а в `messages` — строка outbox.
   Ответ не теряется в мессенджере: вопрос и сообщение записаны одной транзакцией.
5. **База знаний.** Вкладка «Знания»: HR вставляет markdown с frontmatter и нажимает «Загрузить
   и проиндексировать». Затем нажимает на активный документ: открывается исходный markdown, его
   можно исправить и сохранить — воркер переиндексирует документ, а следующий вопрос ассистента
   цитирует его id. Проверка: спросить «Сколько компания компенсирует занятия спортом?» — ответ
   со ссылкой на загруженный документ. Валидация frontmatter возвращает 422 с точным полем.
6. **Роли.** Выйти и войти с `dev-recruiter-token`: Мария Волкова и её вопрос исчезают — доступ
   ограничен в SQL, а не в интерфейсе. Загрузка и редактирование знаний доступны только роли
   `hr_admin`.
7. **Хронология.** В карточке Анны видны переходы по шагам и `risk_assessed` с уровнем, тегами и
   причинами; в карточке Петра — те же события, и его ответ разобран в риски. С ключом модели там
   же появляется `sentiment_classified` с моделью, рубрикой и расходом; без ключа его нет, потому
   что не было вызова. Это аудит решений, а не лог чата.
8. **Живой вопрос.** Если есть второй терминал:

   ```bash
   curl -X POST http://localhost:8000/webhook/max \
     -H "X-Max-Bot-Api-Secret: dev-secret" -H "Content-Type: application/json" \
     -d "{\"update_type\":\"message_created\",\"timestamp\":$(($(date +%s)*1000)),\
   \"chat_id\":1001,\"user\":{\"user_id\":1001},\"message\":{\"sender\":{\"user_id\":1001},\
   \"body\":{\"mid\":\"demo-$(date +%s)\",\"text\":\"С какого дня действует ДМС?\"}}}"
   ```

   Через две секунды в очереди появляется отвеченный вопрос с цитатой `hr/benefits-dms#0`, шаг
   Анны не меняется. Затем тот же запрос с текстом «готово» двигает сценарий дальше. Это разница
   между вопросом и подтверждением шага.
9. **Планировщик.** `make cron` — один проход: напоминания из `reminder_at`, очередь задач,
   доставка outbox. Cron-совместимый процесс, тот же код, что у воркера; exit code виден
   мониторингу.

## Если что-то не так

| Симптом | Причина | Действие |
|---|---|---|
| В кабинете пусто | `make demo` не выполнялся или другой `DATABASE_URL` | `make demo`, затем `make verify-demo` |
| `make demo-data` отказывается работать | `ENVIRONMENT` не `local` | выставить `ENVIRONMENT=local` |
| `Bind for 0.0.0.0:55432 failed` | порт занят другим Postgres | `make nuke`, затем `make demo` |
| `migrate` падает с `Name or service not known` | postgres не поднялся из-за занятого порта | `docker compose rm -sf postgres`, затем `make demo` |
| Риски пусты | не было ответов на опросы | `make demo` заново, проверить вкладку «Все» |
| Вопросы падают в `no_sources` | не выполнен `make ingest` | `make ingest`, затем `make demo-data` |
| `401` в кабинете | токен не совпадает с `ADMIN_TOKENS` | вставить `dev-hr-token` |
| `knowledge index was built with ...` | базу индексировали другим эмбеддером | `make demo-data` |
| Ответ пришёл без цитаты | это баг grounding | не показывать, зафиксировать в `docs/incidents/` |

После защиты: `make nuke` сносит compose-том и локальную демо-базу. Это удаляет и
проиндексированный корпус, поэтому не запускайте его на том, что вам дорого.

## Что сказать про продакшен

Extractive-провайдер — только для демо и eval: `ENVIRONMENT=production` его отвергает, как и
`EMBED_PROVIDER=hashing`. В продакшене — провайдер по 152-ФЗ (GigaChat или on-prem), тот же
контракт, тот же grounding, та же очередь. Переключение — переменные окружения, без миграции.
Латентность и стоимость с реальными моделями записаны в
[актуальных числах](../measurements/current.md), а не здесь. Последний полный прогон провалил
оба гейта задержки: это записано, поэтому демо не обещает p95.
