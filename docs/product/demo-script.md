# Демо за пять минут

Сценарий для защиты: показать новичка, ассистента и кабинет рекрутера на одних и тех же данных.
Всё работает без ключа модели и без токена MAX: ответы собирает детерминированный
extractive-провайдер из тех же фрагментов, что получила бы модель.

## Подготовка (один раз, до защиты)

```bash
cp .env.example .env
make install
make admin-install
docker run -d --name onboarding-pg \
  -e POSTGRES_PASSWORD=onboarding -e POSTGRES_USER=onboarding \
  -e POSTGRES_DB=onboarding -p 5432:5432 pgvector/pgvector:pg16
make migrate
```

Заменить в `.env` три значения на офлайн-режим (ключ модели не нужен):

```dotenv
LLM_PROVIDER=extractive
EMBED_PROVIDER=hashing
MAX_BOT_TOKEN=demo-token
MAX_WEBHOOK_SECRET=dev-secret
ADMIN_TOKENS=dev-recruiter-token:recruiter:rec-1,dev-hr-token:hr_admin:hr-1
```

## Запуск

```bash
make ingest      # 7 документов в pgvector
make demo        # 3 сотрудника, один завершённый онбординг, три вопроса
make run         # терминал 1: API на :8000
make worker      # терминал 2: обработка событий и таймеров
make admin-dev   # терминал 3: кабинет на :5173
```

Открыть <http://localhost:5173>, вставить токен `dev-recruiter-token`.

## Что показывать

1. **Кабинет, список.** Рекрутер `rec-1` видит своих: Анна Смирнова — активный онбординг; на
   вкладке «Все» появляется завершённый Пётр Кузнецов. Прогресс считается по сценарию, а не по
   ответам модели. Шаг назван по-русски: «Команда и наставник», «Документы», «Завершение».
2. **Карточка Анны.** Шаг 3 из 6, текст текущего шага и два вопроса: «Сколько дней отпуска в
   первый год?» — отвечен, с цитатой `hr/leave-policy#0`; «Кто мой наставник?» — передан
   человеку с причиной `restricted`. Это главный кадр: бот отвечает только там, где есть
   источник, и не путает общий текст о наставниках с ответом про конкретного человека.
3. **Очередь вопросов.** На вкладке «Без ответа» два вопроса, на «Все» — три. У каждого есть
   имя сотрудника и причина передачи. Это не «бот не знает», а разные исходы: `restricted` —
   личная тема, `no_sources` — нет источника.
4. **Роли.** Выйти и войти с `dev-hr-token`: появляется Мария Волкова (HR, шаг «Первый день») и
   её вопрос про зарплату с `restricted`. Рекрутер эту карточку не видит — доступ ограничен в
   SQL, а не в интерфейсе.
5. **Хронология.** В карточке Анны видны переходы по шагам, в карточке Петра — `run_completed`
   с его `employee_id`. Это аудит, а не лог чата; события без сотрудника в карточку не попадают.
6. **Живой вопрос.** Если есть второй терминал:

   ```bash
   curl -X POST http://localhost:8000/webhook \
     -H "X-Max-Bot-Api-Secret: dev-secret" -H "Content-Type: application/json" \
     -d "{\"update_type\":\"message_created\",\"timestamp\":$(($(date +%s)*1000)),\
   \"chat_id\":1001,\"user\":{\"user_id\":1001},\"message\":{\"sender\":{\"user_id\":1001},\
   \"body\":{\"mid\":\"demo-$(date +%s)\",\"text\":\"С какого дня действует ДМС?\"}}}"
   ```

   Через две секунды в очереди появляется отвеченный вопрос с цитатой `hr/benefits-dms#0`, а шаг
   Анны не меняется. Затем тот же запрос с текстом «готово» двигает сценарий на шаг «Документы».
   Это разница между вопросом и подтверждением шага.

## Если что-то не так

| Симптом | Причина | Действие |
|---|---|---|
| В кабинете пусто | `make demo` не выполнялся или другой `DATABASE_URL` | `make demo`, проверить `.env` |
| `make demo` отказывается работать | `ENVIRONMENT` не `local` | выставить `ENVIRONMENT=local` |
| Вопросы падают в `no_sources` | не выполнен `make ingest` | `make ingest`, затем `make demo` |
| `401` в кабинете | токен не совпадает с `ADMIN_TOKENS` | вставить `dev-recruiter-token` |
| Ответ пришёл без цитаты | это баг grounding | не показывать, зафиксировать в `docs/incidents/` |

После защиты: `docker rm -f onboarding-pg` (данные демо не нужны).

## Что сказать про продакшен

Extractive-провайдер — только для демо и eval: `ENVIRONMENT=production` его отвергает, как и
`EMBED_PROVIDER=hashing`. В продакшене — GigaChat по 152-ФЗ, тот же контракт, тот же grounding,
та же очередь. Переключение — две переменные, без миграции.
