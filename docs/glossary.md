# Глоссарий

Собран из [glossary.yaml](glossary.yaml) скриптом `make docs-index`. Новый термин
добавляется в YAML, не сюда.

Одно значение на термин. Код, доки и промпты используют эти слова без синонимов.

| Термин | Значение | В коде | См. также |
|---|---|---|---|
| **сотрудник** | Человек в компании, для которого существует прогон онбординга. Идентификатор — `employee_id`. | `employee` | прогон, новичок |
| **новичок** | Сотрудник внутри активного прогона. Роль, а не отдельная сущность. | `newcomer` | сотрудник, прогон |
| **рекрутёр** | Человек, который ведёт прогоны онбординга. Видит только свои прогоны. | `recruiter` | hr-администратор, роль доступа |
| **hr-администратор** | Человек, который владеет базой знаний, сценариями и всеми прогонами. | `hr_admin` | рекрутёр, роль доступа |
| **менеджер** | Человек, который видит сотрудников одного подразделения: имя подразделения стоит в токене. | `manager` | роль доступа |
| **роль доступа** | Одно из прав кабинета: `recruiter`, `manager`, `hr_admin`. Проверяется на каждом роуте. | `role` | кабинет, скоуп |
| **скоуп** | Набор данных, доступных токену: свои прогоны, подразделение или всё. | `scope` | роль доступа, аудитория |
| **сценарий** | Версионированный онбординг-путь: упорядоченный набор шагов с событиями и таймерами. | `scenario` | шаг, прогон |
| **версия сценария** | Целое число. Прогон держит версию, с которой начался; правка сценария не меняет живой прогон. | `scenario_version` | сценарий, прогон |
| **прогон** | Исполнение одного сценария одним сотрудником. Ключ — `(employee_id, scenario_id, scenario_version)`. | `run` | сценарий, шаг |
| **шаг** | Узел сценария: сообщение, ожидание, проверка или конечное состояние. | `step` | сценарий, состояние шага |
| **состояние шага** | Сохранённая позиция прогона: текущий шаг, момент входа, что уже выполнено. | `step_state` | шаг, прогон |
| **событие** | Вход, который может двигать прогон: `employee_created`, `message_received`, `button_pressed`, `file_received`, `timeout`. | `event` | задача, дедупликация |
| **задача** | Единица работы воркера, записанная в таблицу `jobs` в одной транзакции с событием. | `job` | событие, воркер, outbox |
| **просроченное напоминание** | Таймер, срок которого прошёл и который должен стать строкой `outbox`. | `due reminder` | outbox, планировщик |
| **документ базы знаний** | Файл в `knowledge/` с frontmatter. Единственный разрешённый источник фактов для ответа. | `knowledge document` | фрагмент, цитата |
| **фрагмент** | Извлекаемая часть одного документа базы знаний. Идентификатор `chunk_id` стабилен между переиндексациями. | `chunk` | документ базы знаний, цитата |
| **цитата** | Ссылка из ответа на `chunk_id`, который действительно найден для этого вопроса. | `citation` | фрагмент, обоснованный ответ |
| **обоснованный ответ** | Ответ, каждое фактическое утверждение которого подкреплено цитатой из найденного набора. | `grounded answer` | цитата, эскалация |
| **эскалация** | Передача вопроса человеку вместе с причиной и стенограммой. | `escalation` | дефлексия, вопрос |
| **дефлексия** | Вопрос, который бот закрыл без человека. Главная продуктовая метрика. | `deflection` | эскалация, вопрос |
| **аудитория** | Область доступа документа или фрагмента: `all`, `dept:<имя>`, `hr_only`. | `audience` | документ базы знаний, скоуп |
| **кейс оценки** | Вопрос с ожидаемым поведением: обязательные факты, обязательные цитаты или обязательная эскалация. | `eval case` | золотой набор, гейт |
| **золотой набор** | Файл `docs/evals/golden.yaml` с кейсами, по которым считается качество ответов. | `golden set` | кейс оценки, гейт |
| **страта** | Группа кейсов одного типа (`fact`, `acl`, `neardup`, `injection`, `unanswerable`, `morphology`). Гейт цитируется по страте только при не меньше 10 кейсах. | `stratum` | кейс оценки, гейт |
| **гейт** | Число, которое прогон может не пройти. Нижняя граница Уилсона от закреплённого базового прогона, не вкус. | `gate` | базовый прогон, страта |
| **базовый прогон** | Зафиксированный прогон, с которым сравнивают новый. Числа из разных базовых прогонов не сравнивают. | `baseline` | гейт, парный бутстрап |
| **парный бутстрап** | Пересэмплирование одних и тех же кейсов двух прогонов. Даёт дельту и доверительный интервал вместо двух несравнимых чисел. | `paired bootstrap` | базовый прогон, гейт |
| **измерение** | Файл в `docs/measurements/` с командой, окружением, коммитом и числами. Одно событие — один файл. | `measurement` | гейт, базовый прогон |
| **api** | Процесс, который принимает вебхуки, проверяет подпись, ставит события в очередь и обслуживает admin API. Модель не вызывает. | `api process` | воркер, вебхук |
| **воркер** | Процесс, который разбирает очередь: переходы сценария, поиск, генерация, отправка, диспетчеризация, тик напоминаний. | `worker` | api, задача, outbox |
| **планировщик** | Цикл внутри воркера: просроченные напоминания превращает в задачи. Отдельного процесса нет. | `scheduler` | воркер, просроченное напоминание |
| **outbox** | Таблица зафиксированной будущей работы. Таймеры и исходящие сообщения — строки, а не спящие задачи. | `outbox table` | задача, диспетчер |
| **диспетчер** | Компонент воркера: арендует строки `outbox` по каналам и отдаёт их адаптеру канала. | `dispatcher` | outbox, адаптер канала |
| **аренда** | Право диспетчера отправить строку `outbox` в течение срока. Истекла аренда — строку может взять другой воркер. | `lease` | outbox, диспетчер |
| **адаптер канала** | Код одного мессенджера: разбор входящего, отправка, темп. Ядро о мессенджере не знает. | `channel adapter` | канал, профиль канала, входной адаптер |
| **канал** | Мессенджер как адрес плюс профиль возможностей, а не клиент. По умолчанию включён MAX. | `channel` | адаптер канала, профиль канала |
| **профиль канала** | YAML в `apps/api/channel-profiles/`: лимиты отправки, разметка, поддержка кнопок. Проверяется схемой при старте. | `channel profile` | канал, разметка |
| **разметка** | Формат оформления сообщения у канала: `plain`, `html`, `markdown`. Адаптер переводит в него нейтральный текст. | `markup` | профиль канала, адаптер канала |
| **входной адаптер** | Часть адаптера канала: превращает payload вебхука в нейтральное событие и отбрасывает мусор. | `ingress` | адаптер канала, вебхук |
| **вебхук** | HTTP-вход канала: `POST /webhook/{channel}`. Отвечает `200` до работы, работа идёт через очередь. | `webhook` | api, событие |
| **дедупликация** | Отбрасывание повторной доставки по первичному ключу `events`. Одинаковая фраза от двух людей — два разных ответа. | `deduplication`, `dedupe` | событие, доставка |
| **доставка** | Одна попытка мессенджера принести апдейт. Гарантия at-least-once, поэтому доставки дедуплицируются. | `delivery` | дедупликация, вебхук |
| **профиль модели** | YAML в `apps/api/model-profiles/<роль>/`: модель, конверт, цены, версия. Схема проверяется при старте. | `model profile` | роль модели, конверт |
| **роль модели** | Назначение модели: `answer`, `embed`, `rerank`, `classify`, `extract`. Профиль лежит в каталоге роли. | `model role` | профиль модели |
| **конверт** | Параметры вызова модели: `timeout_s`, `max_retries`, `max_tokens`, `temperature`. Живут в профиле, не в коде. | `envelope` | профиль модели |
| **профиль извлечения** | YAML в `apps/api/model-profiles/extract/`: маршрут, пороги уверенности, движок распознавания. | `extraction profile` | извлечение, распознавание |
| **извлечение** | Превращение PDF или скана в markdown через адаптер. Идёт в воркере, не в запросе. | `extraction` | профиль извлечения, распознавание |
| **распознавание** | Чтение текста с растровых страниц. Включается, только если текстового слоя не хватило. | `recognition`, `OCR` | извлечение |
| **индексация** | Запись документа в базу знаний: проверка frontmatter, нарезка на фрагменты, эмбеддинги, запись строк. | `indexing` | документ базы знаний, фрагмент |
| **поиск** | Три шага: фильтр по аудитории и сроку в SQL, векторный и лексический поиск, слияние рангов, переранжирование. | `retrieval` | переранжирование, эмбеддинг |
| **эмбеддинг** | Вектор фрагмента. Ширина задана профилем модели; смена ширины — миграция и переиндексация. | `embedding` | поиск, фрагмент |
| **переранжирование** | Кросс-энкодер поверх слитого списка: оставляет `top 5` для промпта. | `rerank` | поиск |
| **слияние рангов** | Объединение векторного и лексического списков по обратным рангам. | `reciprocal rank fusion`, `RRF` | поиск, переранжирование |
| **рубрика** | Версионированный файл с вопросами классификатора. Правка формулировки — новая версия, не правка файла. | `rubric` | классификатор |
| **классификатор** | Модель с ролью `classify`: получает рубрику и возвращает распределение вероятностей. Метки не выдумывает. | `classifier` | рубрика, риск |
| **риск** | Уровень `low`, `medium`, `high` из тона и тегов ответа на опрос. Считается в `core/risk.py`, не моделью. | `risk` | классификатор, эскалация |
| **кабинет** | Веб-приложение рекрутёра. Читает admin API, бот его не вызывает. | `cabinet`, `cockpit` | admin API, роль доступа |
| **admin API** | HTTP-контракт кабинета под `/admin/api/v1`. Версия в пути; несовместимая правка — новый префикс. | `admin api` | кабинет, контракт |
| **контракт** | Схема или описание поверхности в `docs/contracts/`. Меняется раньше кода. | `contract` | admin API |
| **вопрос** | Обращение сотрудника, которое бот не закрыл или закрыл. Строка в кабинете: статус, исполнитель, решение. | `question` | эскалация, дефлексия |
| **аудит** | Запись действия с актором, временем и результатом. Ошибки и секреты в аудит не попадают. | `audit` | журнал |
| **журнал** | Таблица `audit_log`: кто, что, когда, с каким результатом. Основа доказательств для 152-ФЗ. | `audit log` | аудит, 152-ФЗ |
| **152-ФЗ** | Закон о персональных данных. Требует локализации базы и поручения обработки; доказательства — в `docs/runbooks/152fz-checklist.md`. | `152-fz` | журнал |
