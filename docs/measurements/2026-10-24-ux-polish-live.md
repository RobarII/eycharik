# Живая проверка UX-правок в MAX

- команда: `userbot` (PyMax) в боевом чате `278874685`, вопросы и нажатия вручную; гейты —
  `make lint`, `uv run mypy`, `uv run pytest -m "not integration and not eval"`,
  `ONBOARDING_TEST_DATABASE=... uv run pytest -m integration`, `make docs`
- коммит: `bf10796` (первая половина правок — `bc2121a`, `7c4445a`, `3dccd05`)
- окружение: прод `https://bot.state3407.space`, VPS `85.208.9.104`, `/opt/onboarding`,
  контейнеры `onboarding-api-1`/`onboarding-worker-1`, Postgres `onboarding`
  (`messages=453`, `questions=98`, `events=322` на момент проверки),
  провайдер ответа `openai/deepseek-v4.1-flash` через `opencode.ai`, эмбеддер
  `qwen/qwen3-embedding-8b` через `openrouter.ai`

## Что проверено

| Кейс | Ожидание | Факт |
|---|---|---|
| «Где взять пропуск?» | строка `Источник: …` вместо `[security/badge-access#0]` | `Источник: Пропуска и физический доступ` |
| «Сколько дней длится испытательный срок?» | то же | `Источник: Испытательный срок и наставник` |
| любой вопрос | мгновенная реакция до ответа | «Секунду, ищу ответ в базе знаний…» за 0.9–1.0 с, ответ через 0.1–8 с |
| файл без подписи на шаге документов | подтверждение приёма | «Файл получил…» + объявление следующего этапа |
| файл с подписью-вопросом | подпись уходит в ответ | ответ про зарплату, объявления этапа нет |
| опрос: текст «9» на шкале | ответ записан, не ушёл в базу знаний | «Записал: 9», «Вопрос 2 из 9» |
| оценка ниже порога | уточняющий вопрос | «Что больше всего мешает?», затем «Следующий этап…» |
| завершение сценария | меню вместо тишины | кнопки «Льготы и бонусы», «Спросить HR», «Пройти заново» |
| нажатие «Льготы и бонусы» после `done` | ответ из базы знаний | ответ про ДМС с источником |

## Побочные наблюдения

- Задержка ответа на живом стенде: 0.9–10.7 с, медиана ≈ 2 с; ожидание теперь не выглядит
  поломкой.
- Провайдер вернул пустой completion дважды на «Сколько дней отпуска?» при `max_tokens: 700`:
  бюджет ушёл на рассуждение. После `max_tokens: 1600` ответ приходит с первого раза.
- `/reboot` и `/nextStage` до этого коммита были доступны любому сотруднику; теперь их видят
  только id из `DEMO_EMPLOYEE_IDS` (на демо-стенде переменная пуста).
- Юзербот иногда показывает одно и то же сообщение дважды в истории; в `messages` дублей нет —
  это артефакт чтения, не отправки.

## Что не проверено

- Тихие часы и мягкие напоминания (не реализованы), обращение по имени, предзагрузка картинок.
- Живой прогон на сценарии v1 целиком после всех правок: проверялись отдельные ветки.
