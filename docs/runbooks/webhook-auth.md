# Прогон: вебхуки отклоняются или не приходят

## Симптомы

- MAX сообщает об ошибках доставки; `events` перестаёт расти.
- Каждая доставка отвечает `401`.
- После 8 часов отказов MAX отписывается.

## Проверки по порядку

1. **Доступность**: `curl -v https://$HOST/webhook/max` должен завершить рукопожатие TLS с доверенной
   цепочкой на порту 443, а хост в URL — совпасть с сертификатом. `401` от этого curl — правильный
   ответ: роут есть и отклонил неподписанный запрос.
2. **Настройка секрета**: пустой `MAX_WEBHOOK_SECRET` заставляет роут отвечать `503`. Заголовок,
   который шлёт MAX, — `X-Max-Bot-Api-Secret`; роут сравнивает его за постоянное время. Ротированный
   секрет требует перерегистрации подписки.
3. **Подписка**: запустите заново команду `subscribe` из [deploy.md](deploy.md). Старая подписка на
   мёртвый туннель объясняет тишину.
4. **Время ответа**: роут должен ответить `200` за 30 секунд. Он делает две вставки и не вызывает
   модель. Если p95 подходит к лимиту, подозреваемый — база, а не бот.
5. **Тело**: только `POST` с JSON. Прокси, который буферизует или переписывает тело, не мешает
   проверке секрета, но ломает большие payload; тела больше 1 MB отклоняются с `413`.

## Подтвердите конвейер

```sql
select count(*) from events;
select status, count(*) from jobs group by status;
select * from audit_log order by created_at desc limit 20;
```

Строка `events` без строки `jobs` значит, что транзакция не фиксирует обе; они делят одну
транзакцию, так что это невозможно и стоит инцидента.

## Восстановление

Перерегистрируйте подписку, отправьте `/start` с тестового аккаунта и подтвердите три строки выше.
