# Проверка за десять минут

Три команды отвечают на три разных вопроса:

| Вопрос | Команда | Время |
|---|---|---|
| Собирается ли и проходит ли гейт? | `make verify` | 3–5 мин |
| Работает ли продукт от базы до кабинета? | `make demo` | 2 мин |
| Совпадают ли демо-числа с обещанными? | `make verify-demo` | 3 мин |

Ключ модели не нужен. Демо отвечает детерминированным экстрактивным провайдером, эмбеддинги
хеширующие, сеть не требуется. Живые модели — опция в конце.

## Маршрут

Быстрый путь — три минуты и одна команда:

```bash
make review   # doctor + стек + демо-набор + сверка чисел через admin API
```

Ожидаемо: `doctor: ready.`, затем `verify-demo: ok`, адрес кабинета и токен `dev-hr-token`.
Если демо уже поднято, команда пересоздаёт данные, а не ломается.

Полный путь — десять минут: `make doctor` (§0) → `make verify` (§1) → `make review` (§2) →
[актуальные числа](measurements/current.md) (§3). Каждый шаг ниже говорит, какой вывод считать
успехом и что он **не** доказывает.

Нет Docker или не хочется запускать? Живой стенд — <https://bot.state3407.space>, доступ по
[live-demo.md](live-demo.md). Числа и проваленные гейты — в
[measurements/current.md](measurements/current.md). Демо-счётчики без локального запуска не
проверить: это ограничение, а не обещание.

## 0. Что должно стоять на машине

Docker с compose v2, `make`, `uv`, `python3`, `curl`, Node 22 для кабинета. Локальный Python-venv
создаёт `make install`.

```bash
make doctor
```

Ожидаемо — строка `doctor: ready.` Если есть `FAIL`, там же написано, чего не хватает. Доктор
ничего не запускает и не удаляет.

## 1. Гейт: `make verify`

Один вход, ровно то, что гоняет CI, плюс проверка кабинета. Нужна база: либо compose-сервис
`postgres`, либо контейнер с pgvector. Гейту нужна своя база, не демо-база.

```bash
docker compose up -d postgres
docker compose exec -T postgres createdb -U onboarding onboarding_test
export ONBOARDING_TEST_DATABASE=postgresql+asyncpg://onboarding:onboarding@localhost:55432/onboarding_test
DATABASE_URL="$ONBOARDING_TEST_DATABASE" make migrate
make verify
```

Порт `55432` — это compose; контейнер `onboarding-pg` из раздела «Без compose» держит `5432`, чтобы
пути не сталкивались.

Ожидаемый результат:

```text
ruff: All checks passed!
mypy: Success: no issues found in N source files
import-linter: Contracts: 2 kept, 0 broken.
docs-index ok: N документов
docs ok: N documents
pytest: passed, покрытие >= 85%
admin: lint, typecheck и vitest зелёные
```

Без `ONBOARDING_TEST_DATABASE` команда остановится и попросит базу. Это намеренно: интеграционный
тир без базы ничего не доказывает, а зелёный без него — неправда.

Две вещи в гейт не входят намеренно:

| Что | Команда | Почему отдельно |
|---|---|---|
| Секреты, уязвимые зависимости, синтаксис workflow, shell и Dockerfile | `make security` | требует сети, а гейт обязан работать офлайн |
| Кабинет против настоящего стека | `make admin-e2e-stack` | нужен поднятый compose, а не только база |

## 2. Демо: `make demo` или `make review`

Поднимает стек, наполняет базу, печатает дверь и токен:

```bash
make demo
# open http://localhost:3000 and enter dev-hr-token
```

Что должно быть в кабинете: 3 сотрудника, 69 активных документов, 2 сигнала высокого риска,
2 вопроса без ответа. Эти же числа проверяет `scripts/verify_demo.sh`.

Если есть две минуты, смотрите три экрана в этом порядке:

| Экран | Что искать |
|---|---|
| Прогоны | Анна: заводская ветка, прогресс по шагам, тон «ты» |
| Риски | Пётр: высокий риск, теги, цитата из ответа и причина |
| Вопросы | личный вопрос передан человеку; ответ рекрутёра уходит в outbox |

Это три обещания продукта: сценарий, риск-радар и человек в контуре. Остальное — детали.
Пошаговый маршрут, что показывать на каждом экране, — [demo-script.md](product/demo-script.md).
Пустое состояние: `make demo-data-del`. Полный сброс: `make nuke`.

## 3. Числа: `docs/measurements/current.md`

README не переписывает цифры, а ссылается на сводку. В сводке у каждой строки есть файл измерения,
а в файле — команда, коммит и окружение. Там же сказано, какие гейты прогон не прошёл: последний
полный прогон провалил два гейта задержки, и это записано, а не спрятано.

`make verify-demo` проверяет только демо-счётчики: три сотрудника, два вопроса без ответа, два
сигнала высокого риска и 69 документов. Числа качества и задержки он не проверяет — для них нужен
свой прогон `make eval` с ключом провайдера.

Что проверяется без ключа модели:

```bash
make eval-lint        # контракт набора и сила каждого гейта
make eval-retrieval   # поиск; на хеширующем эмбеддере это диагностика, а не оценка качества
```

`make eval-retrieval` на `hashing` печатает `FAILED recall_at_5`. Это ожидаемо: хеши не умеют
семантику, гейты выставлены под настоящий эмбеддер. Числа настоящего прогона — в
[measurements](measurements/current.md).

## 4. Живые модели, без бюджета (опция)

```bash
cp .env.live.example .env.live   # вписать LLM_API_KEY
make demo-live
```

Профиль `openrouter-free` ходит в бесплатную модель через OpenRouter. Три честных ограничения:

- суточный лимит бесплатного тира: хватает на разговор, не хватает на `make eval`;
- бесплатных эмбеддингов OpenRouter не даёт, поэтому поиск остаётся локальным: ответы живые,
  ранжирование — демонстрационное;
- `429` от бесплатного тира — норма, а не баг: отказ уходит в эскалацию.

Платный профиль на том же ключе (`openrouter-gpt-4.1-mini`) меряется тем же `make eval`;
цена ответа записана в [измерении](measurements/2026-10-23-eval-full-answer-v3-gpt-4.1-mini.md),
а не в этом маршруте. Как включить — в комментариях `.env.live.example`.

## 5. Чего здесь нет

Названо, чтобы никто не додумал лишнего:

| Не проверяется | Почему |
|---|---|
| Настоящий бот MAX | нужен верифицированный токен «MAX для бизнеса»; адаптер проверен на задокументированных payload |
| Файлы из бота в чат | исходящие вложения не сделаны, кроме картинок сценария; входящие документы принимаются и видны в кабинете |
| Настоящий OCR паспорта | входящие файлы хранятся зашифрованными, но не распознаются (ADR 0027) |
| Юридическое окно хранения | механизм протестирован, число за компанией |
| Продакшн-эксплуатация | есть один демо-стенд на VM, SLA и 152-ФЗ-контур — вне этой работы; что он показывает — [live-demo.md](live-demo.md) |
| Качество на настоящей модели без ключа | воспроизводится только своим прогоном по `docs/evals/README.md` |

## Карта доказательств

Каждое обещание в README имеет проверяемый адрес. Если проверяющий не верит фразе, он идёт сюда,
а не в переписку.

| Обещание | Чем доказано |
|---|---|
| Ответ без цитаты не уходит человеку | `apps/api/tests/test_grounding.py`; гейты проверены на силу в `test_eval_gates_have_power.py` |
| Закрытый документ не утекает в ответ | `make eval-acl`; `apps/api/tests/test_evals_acl_matrix.py` |
| Документ из чата лежит зашифрованным | `apps/api/tests/test_inbound_files.py`; удаление — `test_retention.py` |
| Сценарий не сбрасывается и не теряет шаг | `apps/api/tests/test_service.py`, `test_transitions.py` |
| MAX, Telegram и VK идут через один контракт | `apps/api/tests/test_max_e2e.py`, `test_telegram_ingress.py`, `test_vk_ingress.py` |
| Качество и цена не выдуманы | `docs/measurements/current.md`; `make eval` с ключом |
| Демо-числа совпадают с документацией | `make review`; `scripts/verify_demo.sh` |
| 152-ФЗ: что закрыто, а что нет | `docs/runbooks/152fz-checklist.md` |
| Код проходит гейт, а не только доки | `make verify`; CI гоняет те же `make doctor` и `make verify` |
| Пайплайн не стреляет в прод на merge | прод трогает только релиз тега: `.github/workflows/deploy.yml`, [ADR 0028](decisions/0028-one-image-per-commit.md) |

## Если что-то не так

| Симптом | Причина | Действие |
|---|---|---|
| `Bind for 0.0.0.0:55432 failed` | порт занят другим Postgres | `make nuke`, затем `make demo` |
| `migrate` падает с `Name or service not known` | postgres не поднялся из-за занятого порта | `docker compose rm -sf postgres && make demo` |
| `401` в кабинете | токен не из `ADMIN_TOKENS` | вставить `dev-hr-token` |
| `429` от модели | лимит бесплатного тира | ждать сутки или платный профиль |
| `knowledge index was built with 'hashing:1024'` | базу индексировали другим эмбеддером | `make demo-data` |
| `ONBOARDING_TEST_DATABASE is required` | гейт без базы | шаг 1 этой страницы |
