# 0010 — Один вендор для ответа, эмбеддингов и переранжирования

## Контекст

Пилот держал ответы на community-шлюзе (`deepseek-v4.1-flash`), а поиск — на OpenRouter (эмбеддинги `baai/bge-m3`, `cohere/rerank-v3.5`). Два вендора означали два ключа, два режима отказа и две выписки за один продукт.

Модель ответа тоже была нестабильна: при лимите в 700 токенов один вызов из трёх возвращал HTTP 200 с пустым content — reasoning-модель тратила бюджет до того, как написала ответ. Конвейер корректно эскалировал такие случаи человеку (`reason: unavailable`), но демо и оценка не должны зависеть от подбрасывания монеты.

Измерено 2026-10-23, тот же промпт, те же пять фрагментов, по четыре вызова:

| модель | пустые ответы | задержка |
|---|---|---|
| `deepseek-v4.1-flash` (community-шлюз) | 3 / 8 | 2.1–4.8 с |
| `openai/gpt-4.1-mini` (OpenRouter) | 0 / 4 | 1.4–1.8 с |
| `openai/gpt-4o-mini` (OpenRouter) | 0 / 4 | 1.9–3.1 с |
| `deepseek/deepseek-chat-v3.1` (OpenRouter) | 0 / 4 | 6.1–17.0 с |
| `google/gemini-2.5-flash` (OpenRouter) | 0 / 4 | 0.2 с (тело ошибки) |

## Решение

Один вендор: OpenRouter. Один ключ в `LLM_API_KEY`, `EMBED_API_KEY`, `RERANK_API_KEY`.

- ответ: `openai/gpt-4.1-mini`, температура 0.2, 700 выходных токенов, формат ответа JSON;
- эмбеддинги: `baai/bge-m3`, 1024 измерения;
- переранжирование: `cohere/rerank-v3.5`.

Запрос ответа ставит `response_format: json_object`; пустой completion повторяется как транспортный отказ (`EmptyCompletionError`), а не показывается сотруднику.

## Последствия

- `cost_per_answer_rub` вырос с 0.036 до 0.070 (≈ 0.7 ₽ за десять ответов), а p95 упал с 6603 мс до 2343 мс.
- Корректность эскалации вернулась к 1.000; предыдущей модели ещё и нужен был промпт v3, чтобы перестать отвечать на личные вопросы общим текстом политики.
- Один провайдер — одна точка отказа. Порты остаются провайдеро-независимыми: `LLMProvider` уже говорит на языке формы chat-completions OpenAI, поэтому второй вендор — правка настроек, а не переписывание. Офлайн-провайдер `extractive` остаётся запасным путём без сети для тестов и демо.
- Ключ живёт в окружении и не попадает в git. Учёт стоимости читает `LLM_PRICE_INPUT_RUB_PER_1K` / `LLM_PRICE_OUTPUT_RUB_PER_1K`, так что изменение цены — правка конфигурации, а не кода.

## Альтернативы

- Оставить community-шлюз — отклонено: пустые completion не отличить от отказа, если не смотреть каждый вызов, а пилот не может поставлять монетку.
- Локальная модель — отклонено для пилота: GPU-хостинг вне бюджета инфраструктуры клиента, а контракт требует ответ быстрее восьми секунд.
- Два вендора с автоматическим переключением — отложено: порт такое допускает, но фолбэк удваивает матрицу оценки, а у пилота неделя.
